## Replication, Investigation, and Practical Limitations:
This repository contains an extensive reproduction and analysis of the Lottery Ticket Hypothesis (LTH) using VGG-16 on CIFAR-10 and further experiments involving transferability, optimizer stability, and real-world hardware benchmarking.
The goal of this project is to validate the LTH and investigate deeper properties that influence sparse subnetworks (“winning tickets”)—their stability, generalization, and practical usefulness.

**Experimental Phases**
Phase 1 — LTH Replication
We train a full dense VGG-16 and gradually prune weights using Iterative Magnitude Pruning (IMP).
What we tested:
Dense baseline training (200 epochs, SGD)
One-shot pruning (20%)
Full IMP cycle (6 iterations, 20% pruning each)
Rewinding to original initialization w₀

**Key Findings**
Dense accuracy: ~91.25
Winning ticket accuracy (~74% sparsity): ~91.2%
Sparse networks matched dense performance.

Phase 2 — Transferability
We evaluated whether a winning ticket found on CIFAR-10 transfers to CIFAR-100.
Result:
Dense CIFAR-100: ~46% (stopped at around 20 epochs)
Transferred sparse ticket: ~21%
Sparse masks are task-specific and do not generalize across datasets.

Phase 3 — Optimizer Stability (SGD vs AdamW)
We compared pruning masks obtained from two optimizers under identical seeds and schedules.
Result:
Jaccard Similarity (IoU): < 0.50
Shows completely different winning tickets are created depending on optimization dynamics.

Phase 4 — HPC Benchmarking
We tested whether unstructured sparsity reduces inference latency on Mac M4 GPU.
Result:
Speedup: ~0%
Reason: GPUs treat sparse tensors as dense (dense GEMM kernels).
Sparse pruning does NOT improve real inference time unless structured sparsity or special hardware is used.

Phase 5 — LTH Implementation Paradox
We summarize challenges of applying LTH in real practice:
Problem 1: The “Chicken & Egg” Paradox
To find a sparse winning ticket, you must train the full dense model first, so training time does not decrease.
Problem 2: Hardware Incompatibility
Sparse patterns generated by LTH are unstructured, leading to zero real speedup on common GPUs.

Solutions (Future Directions):
Pruning at initialization (SNIP, GraSP, SynFlow)
Dynamic Sparse Training (RigL, SET)
Structured pruning + sparse tensor cores
